# Формат графического пакета `t0` (Graphic Sheet Format Spec)

В данном документе приведено полное документированное описание бинарного формата пакета `t0`, восстановленное по алгоритмам загрузки и отрисовки из Java-класса `a.java` оригинальной игры.

---

## 1. Контейнер пакета (Main Archive Container)
Архив `t0` состоит из заголовка и 20 последовательных независимых графических сегментов:

| Смещение | Размер (Байт) | Тип | Назначение |
| :--- | :--- | :--- | :--- |
| `0x00` | 4 | uint32 | Количество графических сегментов в пакете (`A = 20`) |
| `0x04` | `4 * A` | uint32[] | Смещение (`offset`) каждого из `20` сегментов от начала файла |

Каждое смещение указывает на начало соответствующего графического сегмента. Все смещения представлены в формате **Little-Endian**.

---

## 2. Структура графического сегмента (Graphic Segment Header)
Каждый из сегментов `00` — `17` имеет структурированный заголовок, за которым следуют данные палитры, метаданные кадров и сжатые пиксельные буферы:

1.  **Заголовок палитры:**
    *   `palette_type` (2 байта, `short`): Тип кодирования цвета.
        *   `-30584` / `0x8888`: 32-битный ARGB 8888 (каждый цвет занимает 4 байта).
        *   `17476` / `0x4444`: 16-битный ARGB 4444 (каждый цвет занимает 2 байта, декодируется в 32-битный ARGB).
        *   `25861` / `0x6505`: 16-битный RGB 565 (каждый цвет занимает 2 байта. Цвет `0xF81F` / Маджента используется как хромакей прозрачности).
    *   `num_palettes` (1 байт): Количество палитр в сегменте.
    *   `colors_per_palette` (1 байт): Количество цветов в палитре (по умолчанию `256`, если `0`).
    *   `palette_data`: Массив цветов размером `num_palettes * colors_per_palette` в соответствующем кодировании.

2.  **Заголовок формата пикселей:**
    *   `pixel_format` (2 байта, `short`): Тип сжатия/кодирования пиксельного буфера.
        *   `25840`: Битово-сдвиговое RLE сжатие.
        *   `10225`: Базовое RLE сжатие на основе старшего бита (байт > 127 задаёт длину повтора, следующий байт — индекс цвета; байт <= 127 — одиночный пиксель).
        *   `22258`: Альтернативный алгоритм RLE-сжатия.
        *   `5632`: 4 бита на пиксель (2 пикселя в одном байте: `upper 4 bits`, `lower 4 bits`).
        *   `2048`: 3 бита на пиксель (плотно упакованные 3-битные цвета в байтовом потоке).
        *   `1024`: 2 бита на пиксель (4 пикселя в одном байте: `6-7, 4-5, 2-3, 0-1`).

3.  **Метаданные кадров анимации:**
    *   `num_frames` (2 байта, `short`): Общее количество кадров/под-изображений в сегменте.
    *   Для каждого кадра (`0` ... `num_frames - 1`):
        *   `width` (1 байт): Ширина кадра в пикселях.
        *   `height` (1 байт): Высота кадра в пикселях.
        *   `x_offset` (2 байта, `short`): Координата X начала пиксельных данных в общем буфере `segment_19.bin`.
        *   `y_offset` (2 байта, `short`): Координата Y (или смещение) начала данных.

---

## 3. Физические пиксельные данные (`segment_19.bin`)
*   Сегмент `19` в `t0` содержит плотный, непрерывный массив байт сжатых пикселей для всех кадров всех сегментов.
*   Каждый кадр любого сегмента имеет строго заданное смещение (`x_offset` / `y_offset`) внутри этого глобального пиксельного буфера.
*   При отрисовке кадра движок считывает байты из `segment_19.bin` по указанному смещению, декомпрессирует их в массив пикселей `int[]` в соответствии с `pixel_format`, подставляет цвета из активной палитры и отправляет результирующий массив в рантайм-метод `Image.createRGBImage` для вывода на экран.

*   Спецификация заголовка палитр, кодирование 32-bit ARGB8888, 16-bit ARGB4444, 16-bit RGB565: **CONFIRMED** (содержится в декомпилированном коде `a.java`).
*   Спецификация RLE-декомпрессоров и битовых режимов (Format 10225, 25840, 5632, 2048, 1024): **CONFIRMED** (методы полностью извлечены из `a.java`).
*   Связь смещений кадров с глобальным сегментом `19` в `t0`: **CONFIRMED**.
