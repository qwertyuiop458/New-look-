# Record Format (m8) — точный формат записей SEG0/SEG1/SEG2

**Дата:** 2026-08-15 · **Источник:** g.Z() (g.java:13796), подтверждён декодом 576 записей без сбоев.

## 1. Формат записи

```
[type u8][id u16 LE][x u16 LE][y u16 LE][len u8][len x u16 LE]
```

| Поле | Размер | Семантика | Статус |
| :--- | :--- | :--- | :--- |
| type | 1 байт | тип записи (14 различных в SEG0/1/2) | CONFIRMED |
| id | u16 LE | идентификатор объекта | CONFIRMED (значение) |
| x | u16 LE | координата X (мировые px; значения ≥ 0x8000 = маркеры) | CONFIRMED |
| y | u16 LE | координата Y | CONFIRMED |
| len | 1 байт | число свойств | CONFIRMED |
| props | len × u16 LE | свойства | CONFIRMED (семантика UNKNOWN) |

## 2. Под-блоки

```
[0xC8][len u8][len байт флагов]  — маркер под-блока (g.c(), g.java:13736)
```
- SEG0: 15 маркеров (первый с len=10, остальные len=0)
- SEG1: 11 маркеров (первый len=10)
- SEG2: 7 маркеров (первые два len=10)
- SEG3/4/5: 7 маркеров с len=10 (флаги)

## 4. Наблюдаемые закономерности (без семантических выводов)

- type 10: 401 запись (70%) — доминирующий; props обычно `[5, 0, a, b, c, 0, ...]` (первые 6)
- type 22: len=17; props[2..3] = 110×95, 60×80 и т.п. (размеры)
- type 23: len=12; props[2..3] = 32×32 (размеры)
- type 15: len=5 (короткая форма)
- type 9: len=8; id = 5..220
- x/y: мировые пиксельные координаты (см. world-coordinate-system.md); значения ≥ 0x8000 — маркеры (65535 = -1)

## 5. Кто читает

- SEG0/SEG1/SEG2: **UNKNOWN_STATIC** — не читаются ни миссиями, ни сценариями (см. load-trace.json)
- SEG3: читается миссиями (под-блоки 0..5) — только как границы секций; флаги пропускаются кодом
- SEG4/SEG5: не читаются

## 6. Что НЕ доказано

- семантика каждого type (не присваивается: parser формата известен, consumer — нет)
- семантика props
- семантика флагов под-блоков (10 байт: [ref?][sub_index][...][value]) — UNKNOWN_STATIC
