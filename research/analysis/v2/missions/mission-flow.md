# Mission Flow — доказанные связи структуры миссий

**Дата:** 2026-08-14 · **Источник:** `g.Z(int)` (g.java:13796), `process_all_missions_v2.py`, `mission-flow.json` (по миссиям).

## 1. Общий каркас (CONFIRMED)

```
START (header: n16, F0, bz, cb, bD, bt)
  → поток миссии (m9 seg10..14): записи 0..26 (сущности), 101 (тайлы), 102 (объекты), 103 (данные), 110..172 (скрипты)
  → маркер 99: переключение на m8 seg3 sub X (10 байт флагов, записей нет)
  → возврат в поток миссии
  → ... (повторяется 42–44 раза)
  → завершение потока
COMPLETION — REQUIRES_REAL_RUNTIME
```

## 2. Контексты (порядок секций по миссиям)

| Миссия | Порядок контекстов |
| :--- | :--- |
| mission_00 | m8.s3.b0 → mission → b1 → b2 → b3 → b4 → b5 |
| mission_01 | b0 → mission → b1 → b2 → b3 → b4 → b5 |
| mission_02 | b0 → b1 → b2 → b3 → mission → b4 → b5 |
| mission_03 | b0 → b1 → b2 → mission → b3 → b4 → b5 |
| mission_04 | b0 → mission → b1 → b2 → b3 → b4 → b5 |

(порядок = порядок первых вхождений контекстов в потоке; полный порядок всех 42–44 переключений — в mission-flow.json)

## 3. Что доказано

- **Все переключения** (212 суммарно) идут **только на m8 seg3** (под-блоки 0..5). m8 seg0/1/2 миссиями НЕ используются (потребитель UNKNOWN).
- **m8 seg3** — слои-флаги: каждый под-блок = 12 байт (маркер `0xC8`, len=10, 10 байт флагов), записей нет. Возврат в миссию после исчерпания под-блока (n12 >= n19).
- **Header миссии**: `n16` (число?), `F0` (первый сегмент/флаг), `bz`, `cb` (условно: `bC != 2 && !L`), `bD`, `bt` — значения из данных, семантика REQUIRES_REAL_RUNTIME.
- **Типы записей** (0..26): 0 = MC, 1/2 = персонажи, 3 = враги, 9 = NPC, 10/11/12/14/16/17/20..26 = объекты/предметы — создают сущности с координатами x,y (мировые px) и props.
- **Спец-записи 110..172**: привязаны к последнему тайлу (101) или объекту (102); 3940 шт. по всем миссиям; 27 опкодов общие для всех миссий (ядро скриптов), уникальные: mission_00 {111,129}, mission_02 {128}, mission_03 {131,147}, mission_04 {144}.

## 4. НЕ доказано (REQUIRES_REAL_RUNTIME)

- стартовое условие миссии (что выбирает mission_00..04 и как связаны с сюжетом);
- objective-механизм (какие записи/опкоды = цель);
- completion condition (что завершает миссию и переключает на следующую);
- fail condition (смерть → рестарт/чекпоинт);
- переход mission_00 → 01 → … → 04 (таблица seg0 [1,1,1,1,1] хранит длины, но не порядок);
- save/progression эффекты.
