# Map Format V2 — формат карты настоящего level package

**Дата:** 2026-08-14 · **Источник:** g.java (Z(), спец-парсеры 16742/16860) + `parse_reference_level_v2.py`.

## 1. MAP_NOT_IN_PACKAGE (для m3_0)

**m3_0 — спрайт-пакет сцен, карты в нём НЕТ.** Все сегменты m3_0 начинаются с заголовка
спрайт-листа `df 03 35 .. 0d 01` (формат a.java) и загружаются сценарным загрузчиком
`g.a(a a2, int n, int n2, ...)` как спрайты. Утверждение старого анализа
«m3_0 = уровень 64×64, тайлы 16×16, 3-11 слоёв» — **артефакт неверных границ сегментов**.

## 2. Где реально хранится карта

Карта = данные **миссии** (m9 seg10..14) + объектные слои **m8** (seg0..2):

| Компонент | Где | Формат | Статус |
| :--- | :--- | :--- | :--- |
| тайловые ячейки | миссия (m9 seg10..14) | `[101][tile_id u16][len u8][данные]` | CONFIRMED |
| объекты-декор/стены | m8 seg0..2 | обычные записи type 10/22/23 (с размерами) | CONFIRMED |
| сущности | миссия | записи type 0..26 с координатами x,y | CONFIRMED |
| данные-байты | миссия | `[103][len][байты]` | CONFIRMED (назначение UNKNOWN) |
| спец-записи | миссия | `[110..172][len][len×u16]` | CONFIRMED (семантика UNKNOWN) |

## 3. Тайловая ячейка (опкод 101) — по коду 16860

```
[101][tile_id u16 LE][len u8][len байт]
  данные[0] == 1  ->  начало строки: g.l[данные[1]] = индекс; g.C[данные[1]] = данные[2]
  данные[1]       ->  y (номер строки)
  данные[2]       ->  значение тайла
  данные[3] == 1  ->  g.d[индекс] = true (проходимость/walkable)
  g.H[индекс]     ->  позиция в g.z (массив эффектов)
```
Координата x восстанавливается как порядковый индекс ячейки в строке y
(точная логика x — REQUIRES_REAL_RUNTIME).

**Примеры (миссия 0, m9 seg10):**
```
idx=0   tile_id=16    data=[1,1,1,0]    -> y=1,  value=1,  не проходима
idx=16  tile_id=950   data=[1,7,1,0]    -> y=7,  value=1
idx=29  tile_id=326   data=[1,10,0,0]   -> y=10, value=0
idx=3   tile_id=1003  data=[0,0,0,1]    -> не начало строки, проходима
```

## 4. Объектные записи мира (m8 seg0..2) — по коду Z()

```
[type u8][id u16][x u16][y u16][len u8][len x u16 props]
```
- type 10 (220 записей в seg0): объекты; props[0]=5 (константа), props[1]=0,
  props[2..3] — направление/размер, props[4] — id анимации/паттерна
- type 22: объекты с размерами (props[2..3] = 110×95, 60×80 — размер в px)
- type 23: объекты 32×32 (props[2..3])
- type 15: двери/переходы? (len=5)
- type 14/18: интерактив
- type 9: NPC, type 3: враг
- координаты x,y — мировые пиксельные (до 2626 px; мира 64×64 тайлов НЕТ)

## 5. Чего НЕТ

- тайловой сетки 64×64, «слоёв 3-11», «тайлов 16×16» в m3_0 — не существует (старый анализ ошибочен);
- отдельной маски коллизий в виде битовой сетки уровня — коллизии задаются флагом
  проходимости тайловых ячеек (данные[3] записи 101) и размерами объектов;
- «layer_count 3..32» из levels-master.json — артефакт: 6 слоёв m8 (seg0..5), из них 3 реальных + 3 заглушки.

## 6. Что остаётся неизвестным

- точная семантика спец-записей 110..172 (880 шт. в миссии 0) — REQUIRES_REAL_RUNTIME;
- точная логика x-координаты тайловых ячеек — REQUIRES_REAL_RUNTIME;
- назначение записей 103 (данные) — REQUIRES_REAL_RUNTIME;
- связь tile_id → спрайт-лист (какие сегменты m3_0/m6_*/m7 рисуют тайлы миссии) — REQUIRES_REAL_RUNTIME.
