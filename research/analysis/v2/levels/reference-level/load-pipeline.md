## 2. Цепочка загрузки миссии (`g.Z(int n)`, g.java:13796)

```
z() (выбор миссии) -> g.Z(bB)
  g.a("/m9")                     // открыть m9
  n9 = g.C(n)                    // seg0 m9 = [01 01 01 01 01] — таблица длин; n9 = индекс
  g.a(1), g.a(2)                 // стартовые данные (спец-парсер 101/102/103)
  g.dr()                         // seg4: таблицы сущностей T/U/W/V/X/Y (56 архетипов, 176 анимаций)
  g.eZ()                         // seg5: оружие (16) + патроны (6)
  mission = g.a(10 + n9)         // seg10..14: ДАННЫЕ МИССИИ
  g.ac()                         // закрыть m9
  ...парсинг mission...
  [99][seg][sub]                 // маркер: g.a("/m8") (первый раз), поток = m8 seg<seg> под-блок <sub>
  g.c(n17, seg_m8)               // парсер m8-сегмента: j[seg][k] = позиции маркеров 0xC8
```

## 4. Формат записей потока миссии (подтверждён на m8 seg0: 340 записей без сбоев)

```
обычная запись: [type u8][id u16 LE][x u16 LE][y u16 LE][len u8][len x u16 LE]
  type 0..26   — сущности/объекты (0=MC, 1/2=персонажи, 3=враг, 9=NPC, ...)
маркер:        [99][seg u8][sub u8][1 байт][u16 value]  — переключение на m8 seg.sub
тайловая ячейка: [101][tile_id u16][len u8][len байт: data[0]=маркер строки(1),
                 data[1]=y, data[2]=значение, data[3]=флаг проходимости, ...]
объект:        [102][obj_id u16][len u8]  (len байт не читаются кодом)
данные:        [103][len u8][len байт]
спец-запись:   [110..172][len u8][len x u16]  — скрипты/эффекты
терминатор:    [104..109] — останавливает спец-парсер
```
