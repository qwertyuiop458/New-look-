# Container Format V2 — точная спецификация формата контейнеров ресурсов

**Источник:** `g.java:4055-4075` (`a(String)` — открытие), `g.java:4088-4100` (`b(int)` — чтение сегмента).

## 1. Структура

```
offset 0        : 1 байт  A = число сегментов
offset 1..1+4A  : A x uint32 LE  h[] — таблица смещений
```

- **count size:** 1 байт (НЕ 4 — исправление V1, GAME_BIBLE §13)
- **offset size:** 4 байта, Little-Endian
- **endian:** LE
- **base offset:** `base = 1 + 4*A` (конец заголовка)
- **смещения относительные:** абсолютное смещение сегмента n = `base + h[n] − h[0]`
- **границы сегмента n:** `[base + h[n] − h[0], base + h[n+1] − h[0])`, размер = `h[n+1] − h[n]`
- **доступность:** сегмент n читается только при `n < A−1` (последний сегмент недоступен, `g.b` возвращает null)
- **порядок чтения:** строго последовательный (b(int) делает `skip(h[n] − h[B])` от текущей позиции)

## 2. Примеры

**m0** (3903 Б): A=3, base=13, h=[0, 2893, 3890]
- seg0 = 13..2906 (2893 Б) — данные карты (тайловые индексы)
- seg1 = 2906..3903 (997 Б) — данные (коллизии/скрипты)
- seg2 — недоступен

**m9** (221721 Б): A=16, base=65, h=[0, 5, 231, 847, 1261, 9057, 10091, 11022, 11265, 11661, 14808, 45092, 70668, 137758, 165168, 221656]
- seg4 = 1326..9122 (7796 Б) — **таблица сущностей/анимаций** (теги 6/7/8/9/10)
- seg5 = 9122..10156 (1034 Б) — **таблица оружия/патронов** (теги 0/1)
- seg10..14 = 30284/25576/67090/27410/56488 Б — крупные бинарные блоки

## 3. Табличные форматы внутри сегментов (m9)

### Сущности (loader `g.dr()`, g.java:24553) — m9 seg4
| тег | запись | размер |
| :-: | :--- | :-: |
| 6 | `[id u16][32 x u16 props]` — архетип | 67 Б |
| 7 | `[10 x u16]` — анимация (id отсутствует) | 21 Б |
| 8 | `[2 x u16]` — X (список кадров) | 5 Б |
| 9 | `[2 x u16]` — Y (список кадров) | 5 Б |
| 10 | `[15 x u16]` — кадр | 31 Б |

В рантайме U = 35 полей/архетип (32 из файла + 3 кодом), W = 13 полей/анимация (10 + 3 кодом).

### Оружие (loader `g.eZ()`, g.java:31831) — m9 seg5
| тег | запись | размер |
| :-: | :--- | :-: |
| 0 | `[id u16][28 x u16]` — оружие | 59 Б |
| 1 | `[id u16][6 x u16]` — боеприпас | 15 Б |

Счётчик записей: `g.E() = an.length / 28`.

## 5. История ошибок V1

- GAME_BIBLE §13: «первые 4 байта — количество сегментов» — неверно (1 байт).
- extract_t0.py: читал 4 байта count (случайно сходилось из-за нулевых байтов) и трактовал h[] как АБСОЛЮТНЫЕ смещения — неверно (относительные; база = конец заголовка). Все прошлые сегментные границы смещены.
- Аудит 2a0f0a0: границы сегментов m9/t0 также считались по h[] как абсолютным — поправлено в V2; найденные в аудите «17 weapon records, ID {0,1,9,11,50}» — артефакт сдвига; V2: **16 records, ID {2,3,4,5,6,7,8,11,16,17,18,19,20,21,22,24} + 6 ammo {10,12,13,14,15,23}**.
