# Sprite Format V2 — формат спрайт-листов (a.java)

**Дата:** 2026-08-15 · **Источник:** a.java a(byte[], int) (строки 60-300) — полный статический разбор.

## 1. Структура листа

```
[0..1]      пропуск (++n)
[2..5]      f = u32 LE
[6..7]      c = u16 — число объектов
[объекты]   k=0:  [a u16][b u16][c u16][d u16]          (9 Б)
            k=1/2: [e u32][c u8][d u8]                  (7 Б)  // e = смещение, c = w, d = h (размеры!)
[палитры]   n8 = u16 записей: [tag u8][f u16][g u16][d u8] (6 Б)
[f&0x8000]  n10 = u16 палитр: [4 байта] на палитру
[b-записи]  n6 = u16: [tag u8][e u16] (+ [i u8][k u16] если f&0x8000)
[f-записи]  n5 = u16: [f u8][g u8][i u16][j u16][h u8]  (7 Б)  // вероятно x,y,w,h,флаг
[e-записи]  n4 = u16: [e u8][h u16]                     (3 Б)
[ФОРМАТ]    n10 = u16: 0x8888 | 0x4444 | 0x6505
[g]         u8: число мини-кадров (≤ 8)
[h]         u8 (0 → 256): пикселей на мини-кадр
[пиксели]   g × h пикселей по формату
[магия]     u16 == 25840 (0x64F0) — анимационный лист (опционально)
[блоки]     c = u16 число блоков; [длина u16][данные] — большие кадры (RLE?)
```

## 2. Пиксельные форматы (ПОДТВЕРЖДЕНЫ все три)

| Код | Формат | Декодирование (a.java) |
| :--- | :--- | :--- |
| 0x8888 | 32-bit ARGB | пиксель = u32 LE; альфа: (v & 0xFF000000) != 0xFF000000 |
| 0x4444 | 16-bit ARGB 4444 | (n3 & 0xF000)<<16 | (n3 & 0xF000)<<12 | (n3 & 0xF00)<<12 | (n3 & 0xF00)<<8 | (n3 & 0xF0)<<8 | (n3 & 0xF0)<<4 | (n3 & 0xF)<<4 | n3 & 0xF |
| 0x6505 | 16-bit RGB 565 + alpha | (n3 & 0xF800)<<8 | (n3 & 0x7E0)<<5 | (n3 & 0x1F)<<3; значение 0xF81F (63519) = прозрачный |

**Старое утверждение «8-bit indexed 256 цветов» — ОПРОВЕРГНУТО (уже в V2); подтверждены 4444/565/8888.**

## 3. Магия 0x64F0 (25840)

После пикселей: `this.a == 25840` → вычисление битовой маски: `j = 1 << ceil(log2(h-1)); j -= 1` — маска индексации (для атласной адресации кадров).

## 4. Мини-кадры vs большие кадры

- `a[8][h]`: до 8 мини-кадров по h пикселей (h ≤ 256; 256 = 16×16 тайл).
- Большие кадры: объекты c×d (напр. 240×255) + блоки данных (после 0x64F0) — формат сжатия блоков REQUIRES_REAL_RUNTIME.

## 5. Экспорт

`research/scripts/extract_sprites_v2.py` — декодирует мини-кадры в PNG (по формату 4444/565/8888):
m0 seg0 (4444, 1 кадр), m2 seg1 (8888, 1×255 px), m7 seg6 (8888, 2×250 px) и др. (см. extracted-metadata.json).
Количество PNG ≠ количество спрайтов (полные листы в блоках не декодированы).

## 6. Где лежит графика

- спрайт-листы a.java: сегменты m0/m1/m2/m7/m11_0/m11_1/m13_2 (сценарий g.g(), гл. меню/сцены);
- геймплей: m6_0..m6_5 (a[16..21]) и m7 (a[22]) — загружаются в геймплее (g.java:2501, 33601);
- m13_2 seg0 — MIDI-файл (MThd) — музыка (audio/midi);
- тайлы миссий (tile_id) → конкретный лист: UNKNOWN (REQUIRES_REAL_RUNTIME).
