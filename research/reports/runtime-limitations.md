# Системные ограничения рантайм-среды (Runtime Limitations Report)

Данный отчёт содержит техническое описание причин, по которым прямой динамический запуск оригинальной J2ME-игры не может быть выполнен в текущем окружении песочницы, а также требования для полноценного динамического тестирования.

---

## 1. Технические причины сбоя запуска эмуляторов (Why Emulators Failed)
При попытке запустить J2ME эмуляторы (**FreeJ2ME** или **MicroEmulator**) в текущей песочнице возникают непреодолимые инфраструктурные ограничения:

1.  **Отсутствие графического сервера X11 (Headless Linux):**
    *   *Причина:* Оба эмулятора используют Java Swing / AWT / SWT для создания GUI-окна эмулятора и графического холста (`Canvas`).
    *   *Сбой:* Java Virtual Machine (JVM) выбрасывает критическое исключение `java.awt.HeadlessException: No X11 DISPLAY variable was set, but this program performed an operation which requires it`.
2.  **Сетевая изоляция брандмауэра песочницы:**
    *   *Причина:* Для обхода ограничений headlessness на серверах обычно разворачивают виртуальный фреймбуфер `Xvfb` (X Virtual Framebuffer).
    *   *Сбой:* Попытки установить пакет `xvfb` через системный менеджер пакетов `apt-get` блокируются фаерволом на этапе соединения с репозиториями Debian (`deb.debian.org`).

---

## 2. Недостающие зависимости (Missing Dependencies & APIs)
Для полноценного графического запуска игры на виртуальном устройстве необходимы следующие компоненты, отсутствующие в текущей песочнице:

*   **X11 Display Server:** Виртуальный или реальный графический сервер (X11/Wayland).
*   **GTK / SWT Native Libraries:** Библиотеки сопряжения Java с нативным оконным интерфейсом Linux.
*   **Xvfb / VNC Server:** Для отрисовки буфера экрана в headless-окружении и передачи его в виде графических скриншотов.

---

## 3. Требования для полноценной динамической проверки (Real Runtime Validation Requirements)
Чтобы перевести статус извлеченных данных из `SIMULATED` в `RUNTIME_CONFIRMED`, необходимо выполнить следующие шаги в подготовленной среде:

1.  **Развертывание среды с поддержкой X11:** Использовать контейнер или виртуальную машину с предустановленными пакетами `Xvfb`, `x11vnc` и виртуальным рабочим столом.
2.  **Инструментация оригинального байт-кода (Bytecode Instrumentation):**
    *   Создать копию оригинального JAR в `research/runtime/instrumented/`.
    *   Внедрить логирующие вызовы (например, через ASM или AspectJ) в методы `g.F()` (загрузка карты) и `f.a(byte[], int)` (спаунер), чтобы они выводили точные координаты и стейты в стандартный вывод `System.out.println()`.
3.  **Запуск и логирование:** Выполнить запуск инструментального JAR в эмуляторе headlessly под управлением `Xvfb` и автоматически распарсить логи вызовов для сравнения со статической спецификацией.
4.  **REQUIRES_REAL_RUNTIME:** Все динамические механики (реакции на зажатие клавиш, ИИ зомби, траектории движения камеры) требуют именно такого полноценного динамического рантайма.
